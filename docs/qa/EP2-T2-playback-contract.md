# Contrato de reproducción

El VFD muestra `CARGANDO` al iniciar un intento. `POST /api/play` acepta el comando. La animación informa el acople físico. Después del acople y de reanudar el dispositivo, `discPlayback` solicita una lectura nueva. Para confirmar, `playbackSnapshotCoordinator` exige que esa lectura pertenezca al intento, al álbum y al dispositivo vigentes, informe una pista en reproducción y tenga una marca de tiempo fresca. La confirmación se publica después de restaurar el volumen.

La preparación y el acople disponen de 25 segundos. Desde la reanudación se abre un plazo de 15 segundos para obtener la confirmación. Cuando ese plazo vence, el intento pasa a `degraded`. Un error o cancelación conserva la confirmación anterior y permite reintentar al terminar la recuperación. Las respuestas tardías y los eventos de un intento anterior se descartan. Fuera de un intento, el visor sigue las observaciones del reproductor, incluidos pausa y cambios de pista.

`npm run test:playback-contract` ejecuta las pruebas del coordinador, los plazos, el orden de las observaciones, la recuperación de volumen y la selección de pistas. `npm run test:e2e -- tests/e2e/playback-state-contract.spec.cjs` comprueba el visor y el transporte físico en el build mock con el rail habilitado. Incluye el reintento tras una caída de red y usa la API normal en el segundo intento. El smoke de Spotify requiere una sesión autorizada y el dispositivo web activo.
